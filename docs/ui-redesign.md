# 抖音工作室面板 · 重设计方案

> 2026-11-04 · 参照 Linear / Vercel / Stripe / PostHog / Plausible（2026 dashboard 趋势）与
> Apple iPad 设置、Attio 设置的「分区导航」模式，以及同类的 dsh-douyin-watch / browser-local。

## 一、现在的问题（不是好不好看，是没骨架）

1. **八张卡平铺两栏，没有主次**。每张卡都在争注意力，眼睛不知道先看哪。
2. **页面无限长**。设置卡一个人就两屏（18 个字段），收件箱八条，日报一串，全堆在一页上。
3. **信息没有分层**。今天发了多少、还剩多少额度、哪条该回 —— 这三个是不同量级的事，现在它们长得一样大。
4. **视觉密度不稳**。有的卡是表单，有的是列表，有的是开关组，却共用一套「卡片 + 内边距」外壳。
5. **状态藏在细节里**。要判断「今天还能不能发」，得读一行小字。

## 二、三条路

### 方案 A · 左侧分区 + 右侧内容（像成熟后台）

```
┌──────────┬───────────────────────────────────────────┐
│ 收件箱 3 │  收件箱                     [刷新] [重挑] │
│ 今天     │  ─────────────────────────────────────────│
│ 自主     │  ● 私信  某某  「在吗」       2 分钟前   │
│ 设置     │  ● @我   某某  「这个怎么卖」  1 小时前   │
│ 刷视频   │  ● 评论  某某  「好看」       3 小时前   │
│ 额度     │                                           │
│ 后台     │                                           │
│ 趋势     │                                           │
└──────────┴───────────────────────────────────────────┘
```

- 左栏 104px 竖排，图标 + 文字 + 角标
- 右侧一次只显示一张卡，高度恒定
- 窄屏（< 720）自动改成顶部横向 tab

**优点**：最像正经后台，永不再长。
**缺点**：改造最大，卡片要拆成独立页面；跨卡对照（比如「额度还剩几条」和「收件箱几条」）看不到。

### 方案 B · 单页 + 折叠（改动最小）

现在的八张卡全保留，每张可以折叠，默认只展开收件箱和今天。

**优点**：两天能做完。
**缺点**：只是把长藏起来，展开还是长；骨架问题没解决。

### 方案 C · 工作台三段式（推荐）

```
┌───────────────────────────────────────────────────────┐
│ 小汐 · 已登录 · 盯私信开           粉丝 207  作品 7  赞 4278  │  ← 看板（固定 96px）
│ 今天还能发 36 条  ▓▓▓▓▓▓▓░░░  回评 4/20                 │
├───────────────────────────────────────────────────────┤
│ [待办 3] [今天] [自主] [设置] [刷视频] [额度] [后台] [趋势] │  ← 分段控件
├───────────────────────────────────────────────────────┤
│ 收件箱                                     [刷新][重挑] │
│ ┌───────────────────────────────────────────────────┐ │
│ │ ● 私信 某某 「在吗」            值得回 · 2 分钟前  │ │  ← 内容区
│ │ ● @我  某某 「这个怎么卖」       值得回 · 1 小时前  │ │     固定高度
│ │ ● 评论 某某 「好看」             可以等一下        │ │     内部滚动
│ └───────────────────────────────────────────────────┘ │     (max 380px)
└───────────────────────────────────────────────────────┘
```

**三段**：

1. **看板**（永远在）：账号 + 三个数字 + 额度条。一眼知道「今天还能不能干活」。
2. **分段控件**：八个区，一次只渲染一个。和现在设置卡里的四页 tab 是同一个东西，只是提到整页级别。
3. **内容区**：高度固定（比如 `min(70vh, 560px)`），列表在里面滚，页面本身不再变长。

**优点**：一眼看板 + 永不长 + 改造中等（卡片不用重写，只是被「一次显示一张」包起来）。
**缺点**：跨区对照要切 tab（用看板补上最要紧的那几个数）。

## 三、视觉规范（三个方案通用）

### 颜色：只表达状态

| 用途 | 值 |
|---|---|
| 主色（唯一强调） | `#6f9ff0` 暗 / `#2f6fd0` 亮 |
| 成功 / 警告 / 失败 | `#5fbf82` / `#dbae6b` / `#ef8175` |
| 其余全部 | `currentColor` 的 4% / 8% / 12% / 20% 透明度灰阶 |

**规矩**：除了状态点和一条额度条，界面上不再出现第二种颜色。Vercel 那条经验——「颜色一多，状态色就不响了」。

### 字号：三档，不要四档

| 层级 | 大小 | 字重 |
|---|---|---|
| 主数字 | 20–22px | 660，`tabular-nums`，`-0.02em` |
| 卡片标题 | 13px | 620 |
| 正文 / 字段 | 12.5px | 400 |
| 说明 / 时间 | 11px | 400，60% 透明度 |

### 形状与阴影

- 圆角：卡片 12px（现在 16 偏软）、输入框 9px、胶囊 999px
- **卡片去阴影**，只留 1px 边（Linear 式）。阴影只给看板和浮层，这样「亮的地方」才真的亮
- 卡片之间 12px，卡片内部 14px，分组之间 20px —— 靠间距分层，不靠线

### 密度

- 列表行高 28px（现在约 30），一屏能多看两条
- 表单字段：窄屏一行一个、宽屏两列（现在已经是）
- 所有列表 **限高 + 内部滚动**，永远不许把页面撑长

### 空 / 加载 / 错误

- 空：虚线框 + 一句人话 + 一个动作（「今天还没人找你，去刷会儿视频？」）
- 加载：骨架条（已有 `[data-dys-skel]`）
- 错误：一行红字 + 「重试」，不弹窗

## 四、交互

1. **分段切换记忆**：上次看哪一区，下次还停哪（localStorage）
2. **就地反馈**：保存成功在字段右侧亮 1.5s 勾，不整页提示
3. **数字可点**：看板上点「36 条」跳到额度区，点「回评 4/20」跳到收件箱
4. **键盘**：`/` 聚焦搜索（收件箱），`r` 刷新
5. **危险动作二次确认**：删除/清账这类，按钮变红 + 再点一次（已有 `data-armed`）

## 五、改动量

| 方案 | client.js 改动 | 新代码 | 风险 |
|---|---|---|---|
| A | 大（拆页 + 左栏） | +250 行 | 中：窄屏要另做一套 |
| B | 小（加 details） | +40 行 | 低 |
| C | 中（包一层 tab + 看板重排） | +160 行 | 低：卡片本体基本不动 |

三个方案都要先把 `client.js` 的体量上限从 1700 放到 2100，并在 `check.mjs` 注释写明这一轮是结构改造。

## 六、建议顺序

1. 先做 C 的**骨架**（看板 + 分段 + 内容区定高），视觉规范同批落地 —— 这一步就能把「长」和「没主次」一起解决
2. 用一周，看哪一区最常点；常点的提到前面，冷门的（后台/趋势）收进「更多」
3. 之后再考虑 A 的左栏（如果 C 的切换还是嫌烦）
