## 1. 项目理解

### 1.1 目标与定位

给「小汐」这个 AI 人格做一个**能自主运营单个抖音账号的 DSH 插件**：她自己判断该回什么、
该看什么、该发什么，人只定边界与最后放行。不是给人用的创作工具，也不是多账号 SaaS。

原始六条需求（甲方口径）：
1. 自主发布：封面上传、标签文案、BGM 选择到最终发布的完整流程
2. 回复评论与私信，重点解决：回错到自己、同一人重复回复、无法回复楼中楼、语气与人设卡不一致
3. 主动安利刷到并看完的视频及真实感想，风格如日常推荐
4. 账号支持评论区 @ 我、点赞收藏等互动
5. 刷视频的时间与数量限制：每天几轮、每轮几条、内容偏好、具体发布时间
6. 内置自检，核对流程与规则是否被正确执行

一句更准的定位：**它是「给机器人接入抖音」的能力层 + 给甲方看的观察/审批台**，
这两层的语义必须分开（见 F2-05），否则模型会选错入口、出事也无法归因。

### 1.2 目标用户（三层，当前只服务前两层）

| 层 | 是谁 | 现在怎么用它 | 未被满足的 |
|---|---|---|---|
| 甲方（你） | 产品/设计判断者，重隐私、重质感、要求根因排查 | 看面板、改规矩、点头放行真发 | 风险告知、SLO、审批体验、合规姿态 |
| 机器人（小汐） | 调 `douyin_studio_*` 工具的 LLM | SKILL.md + 32 个工具描述 | 工具契约一致性、风险注解、宿主级确认 |
| 第三方（假想） | 其他 DSH 用户 | README 里写了 `dsh plugin add` | 能力声明、版本兼容、签名、合规（目前不具备，见 X-04） |

### 1.3 架构与数据

- 三层：`lib/`（57 个 mjs，引擎与纯函数）/ `index.js`（1122 行，配置+路由+生命周期）/
  `client.js`（1711 行，单文件面板，宿主按 `exports["./client"]` 加载）。
- 两套入口：`32` 个 `douyin_studio_*` DSH 工具 + `node tools/dy.mjs …` CLI；另有 `40` 条面板 HTTP 路由。
- 样式真源 `assets/panel.css` → `tools/build-client.mjs` 压成一行写回 `client.js`；`check.mjs` 校验一致。
- 数据：`~/.dsh/douyin-studio/`（settings / budget / ledger / notify-state / scan-state /
  rounds.jsonl / runs.jsonl / health.json / STOP / picks.json / self.json / publish-log.jsonl /
  inbox-cache.json 两套目录并存）与 `~/.dsh/douyin-duty/`（watch/duty state、登录二维码）。
- 活宿主：DSH 桌面端进程，**端口每次启动都可能变**（51549 → 58337 → 58921），
  需按进程找监听端口再用 `/api/douyin-studio/config` 试 200 确认；`index.js` 常驻内存，改动需重启。
- 前提：Windows + 已登录抖音的 Chrome/Edge + CDP；零运行时依赖；peerDependencies 指向 DSH 私有包。

### 1.4 关键约束（判定「冲突项」的依据）

工程硬约束（来自 `tools/check.mjs` 与 `docs/PLAN-for-dsh.md` 第 5 节禁区）：
1. 零 npm 运行时依赖；宿主进程内禁止 `spawnSync` / 同步阻塞
2. `client.js` 单文件、行数上限 1940（现 1711）；CSS 改动必须经构建脚本
3. 禁改区 7 个文件 md5 锁定：`budget / api / im-send / publish / publish-steps / publish-cli / publish-cdp`
4. 改 `budget.mjs` 额度数字必须先拿到人的一句「可以」
5. `/inbox` 的 stale 分支不许改成 `await`（会退回干等十几秒）
6. 面板不放「让人替它写内容」的输入框（b20 决策）
7. 不做 >200 行的重构；体量超预算要显式改 `check.mjs` 并写理由
8. 涉及发送一律先 `--dry`，真发要人点头；改 `index.js` 要重启 DSH
9. 不输出 API key / token / 私密日记内容，只引用环境变量名
10. 版本号有两套（`package.json` 0.4.0 / 面板 `b36`），改前端要 `PANEL_BUILD +1`

外部合规约束（2026 当下，已核实）：
1. 《抖音用户服务协议》5.1 禁止「使用任何自动化程序、软件或类似工具接入抖音，收集或处理其中信息、内容」；5.4 平台可不事先通知终止服务（2026-02 更新生效）
2. 2026-07 AutoCMD+ 行政处罚案：借系统底层权限自动化操作抖音/微信被认定不正当竞争，罚 3 万；司法裁定要求「用户授权 + 平台授权」双重授权
3. 2026-05 中央网信办：六类必选标签（含「含有 AI 生成内容」），**内容标注是发布必经环节**，未勾选无法发布；抖音把声明入口提到发布一级页并弹窗，首次教育、多次限流
4. 抖音开放平台需企业资质；「代替用户发布」限党政机关/事业单位；「投稿到抖音」需用户在抖音内完成发布并支持二次编辑
5. 风控会识别固定间隔、行为同质化、CDP/WebDriver 特征；常见后果是影子降权而非立即封禁

历史决策「不做」（来自 `docs/picks-design.md` 第 9 节与 `方案-自主运营` 第 7 节）：
无限下滑刷视频、AI 帮你评论别人的视频、多账号、引依赖、为好看改禁改区、
让人写一句话再发的输入框。这些均在 4.3 节作为备选项保留，不删除。
