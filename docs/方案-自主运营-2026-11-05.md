## 0. 一句话结论

这套东西已经是"值班台"而不是"待办清单"：人只定边界，回什么、发什么由它判断。

## 2. G3 · 运行期自检（本轮已实现）

代码：`lib/selfcheck.mjs`（纯函数，250 行）+ `tools/selfcheck.mjs`（入口）+ `tests/selfcheck.test.mjs`（19 例）。

```bash
node tools/selfcheck.mjs                    # 查今天
node tools/selfcheck.mjs --self-uid 123456  # 带上机器人 uid，能查"回错到自己"
node tools/selfcheck.mjs --json             # 给面板/CI
```

退出码 0 = 通过，1 = 有 error。它**只读盘**，不发请求、不写文件，值班间隙可以随便跑。

### 十条规则

| 代号 | 查什么 | 为什么值得查 |
|---|---|---|
| `reply-to-self` | 账本里有回给机器人自己的 | 她会跟自己对话，而且从界面看不出来 |
| `dup-cid` | 同一条评论回了两次 | 闸①应该挡住；挡不住就是闸坏了 |
| `dup-root` | 同一栋楼回了两次 | 闸⑤；楼中楼最容易漏 |
| `over-author` | 同一个人一天超 N 条 | 闸④；11-05 就是这里参数名写错，从头到尾没生效 |
| `quiet-hours` | 静音时段发出去了 | 静音只该拦主动，但记录了就是记录 |
| `author-uid-missing` | 今天有回复没记作者 uid | **闸④对它完全无效**（11-05 抓到的真 bug，20 条记录 0 条有 uid） |
| `future-record` | 记录时间在未来 | 时钟错会让所有时间窗一起错 |
| `budget-day-stale` | 额度账本跨天没重置 | 跨天后额度不重置 = 第二天一开就没额度 |
| `budget-over` | 某渠道超日限 | 只在给了 `limits` 时判，绝不猜上限 |
| `scan-round-empty` | 开着轮次但每轮 0 条 | 配置自洽性；跑了也不看东西 |

### 设计取舍

- **纯函数**：不读盘、不看时钟（`now` 由调用方传），所以能单测，也不会因为"自检自己出错"污染状态。
- **拿不准就 warn**：没有 `selfUid` 时跳过并明说，不误报。假警报会让自检本身被忽略。
- **只报事实不猜原因**：每条 issue 都带 `evidence`（具体哪条 cid / 哪个 uid）。

实测：`node tools/selfcheck.mjs` 在真实数据上跑通，当前唯一提醒是"不知道机器人 uid"——这正是 G1 之外的另一个小缺口：**uid 没有落盘**，建议在 `index.js` 拿到 `/status` 后写进 `autopilot-state.json`。

## 3. G1 · 人设单一真源（建议下一步，半天）

**问题**：小汐的人设卡在 `~/.dsh/profiles/desktop/qq-pet/identity.md` + `style.md`（每轮由 cute-hook 注入）。
抖音插件却读 `settings.json` 的 `persona`，而它是空的 → 自动回复走"通用助手口吻"。
同一个人在两个平台说话不像，根因不是模型，是**两份人设、只有一份在喂**。

**改法**（`lib/settings.mjs` 的 `personaLine`）：

1. `persona` 非空 → 用它（显式覆盖，保持现在的行为）
2. `persona` 为空 → 读 `qq-pet/identity.md` 的前 200 字 + `style.md` 里"说话方式"小节，拼一句
3. 都没有 → 返回空（回到通用口吻，不报错）

加一个 `personaSource` 设置项：`card`（默认）/ `custom` / `off`，面板可切。
风险：只影响提示词前缀，不改发送逻辑；建议先 `--dry` 跑三条看口吻再真开。

## 4. G2 · 点赞 / 收藏（建议排期，但要先想清楚）

现状：`api.mjs` 只有读计数。要做"点赞收藏"需要新增写接口（digg / collect），这是**风控敏感区**，
和 `budget.mjs`、`api.mjs` 同级，属于文档里标"禁改"的那一类。

建议分两步，不要一步到位：

1. **先做只读确认页**：挑卡里给"她看完且高分"的视频加一个"值得赞"的标记，人点一下才真赞。
   这一步不新增写接口，只加一个按钮 + 一条额度通道。
2. **再谈自动**：等 ① 的额度模型（每小时几次）和 ② 的失败退避都有了，再考虑自动赞。
   一次性批量点赞是新号最典型的机器行为特征。

在方案里我把它标成 **P2，且必须先在测试号上跑**——不建议在现在这个已经养了粉丝的号上试。

## 5. 参数建议（基于现有默认值）

| 项 | 建议 | 理由 |
|---|---|---|
| 每天刷几轮 | 3 轮（`scanRounds=3`） | 再多会挤占 `duty` 的额度，且行为太规律 |
| 每轮几条 | 8–10 条（`scanPerRound=10`） | 10 条 × 6 秒 ≈ 一轮一分钟，不会一口气刷穿 |
| 时段 | 09:00–22:00，间隔 240 分钟 | 与人作息重合；凌晨刷最像脚本 |
| 内容偏好 | `minDigg=0` + `minSec=5 / maxSec=180` + 屏蔽词 | 先用宽口径收集，跑一周再收紧 |
| 发布 | 每天 1 条（`publishPerDay=1`），只在低峰 | 发布是最贵的动作，低峰省钱也不容易被判异常 |
| 回评 | 每轮最多 2 条（`replyMaxPerRound=2`） | 宁可少回，不要连着回 |
| 评论时效 | 48 小时（`replyFreshHours`） | 老评论翻出来回最容易显得机械 |

## 7. 不做的事（写清楚，免得下次又讨论一遍）

- 不做"让人写一句话再发"的输入框 —— b20 已经证明实际用法是它自己判断。
- 不在宿主进程上加同步子进程 —— 一个 `spawnSync` 就能把整个 DSH 卡死。
- 不把 `/inbox` 的 stale 分支改成 `await` —— 会退回"干等十几秒"。
- 不为"好看"改禁改区（`budget.mjs` / `api.mjs` / `im-send.mjs` / `publish-*.mjs`）。
