# 调度与界面优化方案

> 2026-11-05 · 参考 n8n / Home Assistant / changedetection.io / Linear / Stripe / Vercel 的做法，
> 逐条对应到本插件现有的字段与代码位置。**这份是建议，没有动代码。**

---

## A. 时间与轮次

### 现在的问题

| # | 问题 | 证据 |
|---|---|---|
| A1 | **两套时间语义并存**：`scanFrom/scanTo`（窗口）+ `scanEveryMin`（间隔）同时在用，改一个另一个还生效 | `lib/settings.mjs` 里两组字段都在 DEFAULTS |
| A2 | **间隔完全固定**（240 分钟），触发时刻等距 | `scanEveryMin: 240` |
| A3 | **轮次不看额度**：额度为 0 也会照常刷一轮 | `feed` 与 `budget` 没有联动 |
| A4 | **失败没有退避/熔断** | HANDOFF 第 10 节「还没做的」自认 |
| A5 | **不知道下一轮几点** | 面板只有"上一轮"，没有"下一轮" |

### 建议

**A1 · 废弃 `scanEveryMin`，统一成"窗口 + 次数"**

```
scanWindows: [
  { from: '09:00', to: '12:00', times: 2 },
  { from: '14:00', to: '22:00', times: 3 },
]
```

- 每个窗口内均匀撒 `times` 个点，再各自加抖动（见 A2）
- 旧字段保留只读映射（`scanEveryMin>0` 时换算成 1 个窗口），不破坏已有配置
- 参考：n8n 的 Schedule Trigger 用「interval / cron / 指定时段」三选一，不允许两套并存

**A2 · 加抖动（jitter）**

触发时刻 = 目标时刻 ± 15%（240min → 204–276min），且两次间隔 ≥ 45min。

- 依据：changedetection.io 的 recheck jitter、Huginn 的 schedule drift
- 收益：行为不再是"每 4 小时整一次"，降低被判定为脚本的概率；也避免每轮都撞在同一批在线用户上

**A3 · 额度联动**

```js
if (budget.stats().messages.left <= 0) return { skipped: 'quota' }   // 不消耗轮次
```

- 收益：额度耗尽时不再空跑浏览器（现在每轮要起页面，是纯浪费）
- 同时把 `skipped` 写进 `rounds.jsonl`，面板能显示"今天 2 轮因额度跳过"

**A4 · 指数退避 + 熔断**

| 连续失败 | 动作 |
|---|---|
| 1–2 次 | 下一轮延后 2× |
| 3–5 次 | 延后 4×，并在面板标黄 |
| ≥6 次 | 停到次日 00:00，写 `runtime/health.json`，面板标红 |

- 依据：n8n 生产实践里那条「只对幂等节点自动重试，并要退避」；非幂等节点（发布/发送）一律不重试
- 收益：账号被风控时不会一直撞墙

**A5 · 可观测**

每轮追加一行到 `~/.dsh/douyin-studio/rounds.jsonl`：

```json
{"at":"2026-11-05T10:12:03Z","round":3,"took":41,"seen":10,"kept":4,"skipped":""}
```

面板顶部一行：「下一轮 15:32（±4 分钟）· 暂停」。暂停复用已有的 `STOP` 文件，做成按钮即可。

## B. 页面布局与交互

### 现在的问题

| # | 问题 | 证据 |
|---|---|---|
| B1 | 看板三个数是粉丝/作品/获赞 —— 虚荣指标，不是"现在要不要动手" | `[data-dys-stat]` 渲染 `u.follower / aweme_count / total_favorited` |
| B2 | 数字只有 15px，和卡片标题同重 | `[data-dys-stat] b{font-size:15px}` |
| B3 | 收件箱是卡片列表，一屏 5 条，无法纵向扫 | `client.js` 列表渲染 |
| B4 | 没有"她今天干了什么、为什么没干" | 只有 `今天做了什么` 的成功记录，没有 skip 原因 |
| B5 | 时间设置是 4 个裸输入框 | 11-05 修过顺序，但仍是"四个框" |
| B6 | 空态只有一句话，没有动作 | `[data-dys-empty]` |

### 建议

**B1/B2 · 看板换指标 + 放大**

| 位置 | 现在 | 改为 |
|---|---|---|
| 左 | 粉丝 | **待回 N 条**（收件箱未处理数，可点跳转） |
| 中 | 作品 | **今日额度剩 N**（已有 herobar，数字提上来） |
| 右 | 获赞 | **上一条回评 · 成功/失败**（点开看原因） |

数字 15px → 22px / 660 / `tabular-nums`；粉丝挪回「粉丝趋势」卡（那边本来就有）。
依据：Stripe 首页只留一个 hero metric，Mercury 用"一个数字建立信任"。

**B3 · 收件箱改表格**

列：`类型 | 谁 | 说了什么 | 判定 | 时间`，行高 28，hover 才出"回复/忽略"。
依据：Stripe 把表格当主界面（列对齐 + tabular figures + 淡网格线）。

**B4 · 加一条"值班日志"**

一行一条：`14:02 看到 3 条 → 判 1 条该回 → 回了「…」` / `15:30 跳过：静音时段`。
这是把"自主执行"从 8 个开关变成可审计的同事，也是 2026 年 Attio 那类产品的分水岭。

**B5 · 时间设置折成两张卡片**

```
┌ 低峰一 ──────────────── [开] ┐   ┌ 低峰二 ──────────────── [关] ┐
│ 00:30 → 08:30               │   │ 未启用                        │
└─────────────────────────────┘   └───────────────────────────────┘
```
四个裸框换成两张卡：一对时间 + 一个开关，视觉上就不可能拆错。

**B6 · 空态给动作**

「今天还没人找你 → [去刷一轮] [看昨天]」。依据：Vercel 的空态被当成 onboarding 而不是错误页。

## C. 优先级

| 序 | 事项 | 改动面 | 风险 | 收益 |
|---|---|---|---|---|
| 1 | A3 额度联动 | `lib/feed.mjs` 10 行 | 低 | 省掉空跑 |
| 2 | A5 下一轮 + 暂停按钮 | `client.js` + `schedule.mjs` | 低 | 心里有数 |
| 3 | A2 抖动 | `lib/schedule.mjs` | 低 | 去机器特征 |
| 4 | B1/B2 看板换指标 | `client.js` | 低 | 一眼知道要不要动手 |
| 5 | A4 退避熔断 | `lib/duty.mjs` | 中 | 风控时不撞墙 |
| 6 | B3 收件箱表格 | `client.js` | 中 | 扫得快 |
| 7 | A1 窗口制 | `settings.mjs` + `schedule.mjs` | 中 | 配置不再打架 |
